# Conduct

Run only when explicitly invoked. This session mode lasts until the user changes it.

## Divide the work

You own scope, assignments, decisions, integration, and the conversation with the user.
Delegate research, implementation, testing, and review that another agent can complete
independently. Work directly when the task needs context or authority only you hold, or
when the task is smaller than the handoff.

Use the host's available agents and the user's model preferences. If delegation is
unavailable, say so and carry out the assignments in order. Only the session holding the
user's request starts workers; workers report an oversized assignment instead of recruiting.

Each assignment names:

- The result required and the evidence that will prove it.
- The files or area it owns, dependencies, and behavior to preserve.
- Relevant decisions, task contracts, and resources.
- What to return: changes, checks, unresolved decisions, and observations outside scope.

Keep overlapping edits in order. Ask workers to read existing material, replace claims
their change makes wrong, and remove resulting duplicates. Requirement changes use
[amend mode](../../docs/amend-mode.md): update the current body and preserve accepted
history in its change records. This does not authorize unrelated cleanup.

## Check and integrate

Check each return against its assignment. Inspect the diff and verification evidence;
run the required checks on the combined result. Look for additions that should have
replaced existing code or text. Accept, request a correction, or drop the result with
a reason. Resolve disagreements explicitly.

A fresh reviewer can perform the check, but you own the decision and the integrated
result. Use a fresh critic for a draft that commits substantial spend, safety, a user
promise, or a contract shared by several workers. Ask for concrete gaps in coverage,
consistency, and feasibility. Use a direct read for simple drafts; add another critic
only when a real contradiction remains. Do not create a separate approval ledger.

## Keep the session moving

Report meaningful progress and continue independent work while waiting. Use existing
authorization. Ask for unresolved scope, cost, irreversible actions, or information only
the user can supply. Report an approach that has failed twice without new evidence.

For a backlog, `run-wave` owns batch scheduling and reconciliation. Workers use
`test-driven-dev` for implementation. `judge-idea` remains a separate, explicitly
requested document review. Those skills keep their own scope and invocation rules.
